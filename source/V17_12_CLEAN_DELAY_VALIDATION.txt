Rings delay cleanup:
- Root cause of the new metallic/breakup character was found in the v17.11 long-delay path.
- v17.11 stored the delay at 11.025 kHz / 16-bit and accumulated four full-rate samples at 0.5 each.
  A steady input therefore wrote about 2x the intended amplitude into the 16-bit delay memory, so strong
  Rings signals could clip inside the delay buffer before the final output meter showed clipping.
- v17.12 moves the Rings delay to 22.05 kHz / 16-bit mono storage (2:1 rather than 4:1 decimation).
- The decimator now averages two samples at 0.5 each, so constant-signal write gain is unity.
- Full-rate output still uses fractional interpolation and the feedback path retains gentle damping.
- Delay range remains 20..1500 ms; Feedback remains 0..85%; Mix remains 0..100%.
- Reverse remains removed.

Memory optimization:
- 33,088 delay samples are split across normal RAM and .pool rather than requiring one large contiguous RAM array.
- Normal-RAM delay portion: 26,000 x int16 = 52,000 bytes.
- Pool delay portion: 7,088 x int16 = 14,176 bytes.
- Final device memory: RAM .data+.bss 86,128 / 98,304 bytes; pool 331,304 / 344,064 bytes.
  This leaves ~12 KB headroom in each region.
