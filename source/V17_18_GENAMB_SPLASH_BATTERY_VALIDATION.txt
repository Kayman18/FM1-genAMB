2. Battery percentage root cause and fix
----------------------------------------
Root cause in v17.17:
- The UI called plat_battery_pct(), but the FM-1 battery ADC was being converted from the stock four-bar thresholds:
    raw >= 591 -> 100%
    raw >= 561 -> 67%
    raw >= 531 -> 33%
    otherwise -> 0%
- Therefore any battery reading above 591 displayed 100%, potentially for a large part of the discharge cycle.

v17.18 behaviour:
- Reads the same FM-1 battery divider on ADC channel 3.
- Uses a continuous estimate instead of treating the top stock bar as 100%:
    raw 505 -> 0%
    raw 610 -> 100%
    linear interpolation between those endpoints
- Filtering is kept in Q8 fixed point. This prevents the integer-IIR dead band where a slowly moving ADC can appear frozen when each update is less than the divisor.
- The ADC is sampled at approximately 1 Hz when the analog peripheral is available.
- An enumerated, awake USB host is shown as "USB" in the header instead of a misleading "100%".
- The FM-1 has no separate charger-detect line exposed to this firmware. A power-only USB source cannot reliably be distinguished from battery power, so that case still uses the voltage estimate.
- This remains a voltage-based estimate, not coulomb counting; lithium discharge is not perfectly linear, so the displayed percentage should be treated as approximate.
